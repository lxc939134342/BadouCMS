# BadouAdmin 插件开发指南

本文档旨在为 BadouAdmin 开发者提供插件编写的指导，帮助您理解插件的结构、生命周期以及如何与系统进行交互。

## 1. 插件目录结构约定

BadouAdmin 的插件（或称模块）通常位于 `modules/` 目录下。每个插件应该有自己独立的目录，例如 `modules/your_plugin_name/`。

一个典型的插件目录结构可能包含以下部分：

```
modules/
└── your_plugin_name/
    ├── .modulerc         # 模块文件列表配置 (系统自动生成或维护)
    ├── info.ini          # 插件基本信息配置文件
    ├── YourPluginName.php # 插件入口文件 (通常与插件目录同名)
    ├── bootstrap.stub    # 插件引导文件 (用于全局导入JS/CSS等资源)
    ├── protectedFiles.php # 系统文件备份配置，插件如果需要替换系统原来文件，可以将系统中需要替换的文件路径写入文件中，插件关闭后恢复原来系统文件
    ├── app/              # 插件的应用程序代码（会复制到根目录的app下）
    │   ├── admin/        # 后台相关代码
    │   │   ├── controller/ # 后台控制器
    │   │   ├── lang/       # 后台语言包
    │   │   └── view/       # 后台视图文件
    │   ├── index/        # 前台相关代码
    │   │   ├── controller/ # 前台控制器
    │   │   ├── model/      # 模型文件
    │   │   └── route/      # 路由文件
    ├── library/          # 插件的库文件
    ├── public/           # 插件的公共资源 (CSS, JS, 图片等)
    │   └── modules/your_plugin_name/
    │       ├── js/
    │       └── css/
    └── template/         # 插件的模板文件 (如果插件有自己的独立模板)
        └── your_plugin_name/
            └── default/
                └── ...
```

## 2. 插件基本信息 (`info.ini`)

每个插件必须包含一个 `info.ini` 文件，用于定义插件的基本元数据。

```ini
name = your_plugin_name
title = 您的插件名称
intro = 您的插件简介
author = 您的作者名称
website = 您的网站或项目地址
version = 1.0.0
state = 1
```

-   `name`: 插件的唯一标识符，通常与插件目录名相同。
-   `title`: 插件的显示名称。
-   `intro`: 插件的简要介绍。
-   `author`: 插件作者。
-   `website`: 作者或插件的网站。
-   `version`: 插件版本号。
-   `state`: 插件的当前状态（1 为启用，0 为禁用）。

## 2.1. 插件引导文件 (`bootstrap.stub`)

`bootstrap.stub` 文件是一个可选的引导文件，其主要作用是在插件启用后，将插件所需的 JavaScript 或 CSS 文件全局导入到系统中。通过在此文件中引入资源，可以确保这些资源在整个应用中可用。

**作用：**

-   **全局资源导入**: 方便地将插件的 JS 和 CSS 文件加载到前端页面。
-   **简化管理**: 集中管理插件的全局资源引入，避免在多个视图文件中重复引用。

**示例 (`bootstrap.stub`)：**

```php
<?php
// modules/your_plugin_name/bootstrap.stub
// 例如：全局加载富文本js
<!-- nkeditor start -->
<link rel="stylesheet" href="__CDN__/modules/nkeditor/themes/black/editor.min.css" />
<script src="__CDN__/modules/nkeditor/NKeditor-all-min.js"></script>
<script src="__CDN__/modules/nkeditor/lang/zh-CN.js"></script>
<script src="__CDN__/modules/nkeditor/index.js"></script>
<!-- nkeditor end -->

```

**注意：**

-   `bootstrap.stub` 文件通常在插件启用时被加载。
-   确保文件中的代码不会引起冲突或性能问题。

## 3. 插件入口文件 (`YourPluginName.php`)

插件的入口文件通常与插件目录同名，并位于插件的根目录下（例如 `modules/your_plugin_name/YourPluginName.php`）。这个类是插件的核心，负责定义插件的生命周期方法和初始化逻辑。

```php
<?php

namespace modules\your_plugin_name;

use app\common\library\Menu; // 引入 Menu 类
use think\facade\Log; // 用于记录日志

class YourPluginName
{
    /**

     * 可以在这里引入公共函数文件、绑定服务、注册事件监听等
     * @return array
     */

        //     // 您的初始化逻辑
        // });
        // 监听模型中的事件
        //  Event::listen('app\admin\model\cms\Content.BeforeUpdate', function ($data) {
        //     p($data->getData());
        // });

        // 示例：在列表页面头部增加一个按钮
    //      function toolbarFilter($content)
    //         {
    //             if (request()->controller() == 'cms.ContentSort') {
    //                 $pattern = '/(<script\s+type="text\/html"\s+id="toolbar">)(.*?)(<\/script>)/is';
    //                 $url = 'cms.content/copy';
    //                 $replacement = '$1$2

    //     <i class="fa fa-copy"></i>

    // </a>$3';

    //             }
    //             return $content;

    }

    /**
     * 插件安装时调用
     * 创建菜单、执行数据库安装、文件拷贝等操作
     * @return bool
     */
    public function install()
    {
        try {
            // 示例: 执行SQL文件
            // \think\facade\Db::execute(file_get_contents(__DIR__ . '/install.sql'));

            // 定义插件的菜单结构
            // Menu::create 方法接受一个菜单数组，其中可以包含 sublist 来定义子菜单。
            // 菜单的 name 字段通常用作权限标识，建议使用插件的唯一标识符作为前缀。
            // 确保菜单数组中的字段（如 pid、name、title、url、type、status、weigh、ismenu 等）
            // 与 AdminRule 表的字段定义以及 Menu 类内部处理逻辑一致。
            // 特别是 status 字段，Menu.php 中使用的是 'normal' 和 'hidden' 而非 1 和 0。
            $menuList = [
                [
                    'name'   => 'your_plugin_name',
                    'title'  => '您的插件',
                    'icon'   => 'fa fa-plug',
                    'url'    => 'your_plugin_name/index/index',
                    'type'   => 1,
                    'status' => 'normal',
                    'weigh'  => 0,
                    'ismenu' => 1,
                    'sublist' => [
                        [
                            'name'   => 'your_plugin_name/sub/index',
                            'title'  => '子功能列表',
                            'icon'   => 'fa fa-list',
                            'url'    => 'your_plugin_name/sub/index',
                            'type'   => 1,
                            'status' => 'normal',
                            'weigh'  => 0,
                            'ismenu' => 1,
                        ],
                        // ... 更多子菜单或权限规则
                    ]
                ]
            ];

            // 调用 Menu::create 方法创建菜单
            Menu::create($menuList);

            return true; // 安装成功返回true，失败返回false
        } catch (\Exception $e) {
            Log::error('插件安装失败: ' . $e->getMessage());
            return false;
        }
    }

     * 删除菜单、执行数据库清理、文件删除等操作
     * @return bool
     */
    public function uninstall()
    {

            Menu::delete('your_plugin_name');

            Log::error('插件启用失败: ' . $e->getMessage());

     * 关闭菜单

     */

            Menu::disable('your_plugin_name');

            return false;
        }
    }
}
```

-   **`AppInit()`**: 在应用初始化阶段被调用。这是插件注册服务、事件监听、引入公共函数等操作的最佳时机。
-   **`install()`**: 在插件安装时执行。您可以在此方法中创建数据库表、初始化数据、拷贝必要文件以及创建后台菜单等。
-   **`uninstall()`**: 在插件卸载时执行。您可以在此方法中清理插件创建的数据库表、删除文件以及删除后台菜单等。
-   **`enable()`**: 在插件启用时执行。您可以在此方法中启用后台菜单。
-   **`disable()`**: 在插件禁用时执行。您可以在此方法中禁用后台菜单。

## 4. 路由定义

插件可以定义自己的路由规则，通常在 `app/index/route/your_plugin_name.php` 中。

> 路由定义时需要注意切勿与 cms 的路由冲突了

```php
<?php
// app/index/route/your_plugin_name.php

use think\facade\Route;

// 定义插件前台路由
Route::group('your_plugin_name', function () {
    Route::get('index', 'index/Index/index'); // 访问 modules/your_plugin_name/app/index/controller/Index.php 的 index 方法
    Route::get('hello/:name', 'index/Index/hello');
})->ext('html'); // 可选：设置路由后缀
```

## 5. 控制器、模型、视图和语言包

插件的控制器、模型、视图和语言包应遵循 ThinkPHP 的模块化开发规范，并放置在插件目录下的 `app/` 相应子目录中。

-   **控制器**: `app/admin/controller/your_plugin_name/` 或 `app/index/controller/your_plugin_name/`
-   **模型**: `app/index/model/your_plugin_name/`
-   **视图**: `app/admin/view/your_plugin_name/` 或 `template/your_plugin_name/default/`
-   **语言包**: `app/admin/lang/zh-cn/your_plugin_name/`

## 6. 公共资源 (`public/`)

插件的静态资源（如 JavaScript、CSS、图片）应放置在 `public/modules/your_plugin_name/` 目录下。这样可以通过公共 URL 直接访问。

例如，`public/modules/your_plugin_name/js/main.js` 可以通过 `__ROOT__/modules/your_plugin_name/js/main.js` 访问。

## 7. 插件与主系统交互 (钩子/事件)

BadouAdmin 可能通过钩子（Hooks）或事件（Events）机制来实现插件与主系统的交互和扩展。虽然具体实现细节需要查阅 BadouAdmin 的核心代码或文档，但通常的模式如下：

-   **定义钩子/事件**: 主系统在特定执行点触发事件。
-   **监听事件**: 插件通过监听这些事件来插入自己的逻辑。

例如，如果系统在用户登录后触发 `user_login_success` 事件，您的插件可以监听此事件并执行一些操作：

```php
// 在插件的 AppInit() 方法中注册监听
\think\facade\Event::listen('user_login_success', function($user_id){
    // 插件的业务逻辑，例如记录登录日志
    \think\facade\Log::info('用户 ' . $user_id . ' 登录成功，由插件处理。');
});
```

请查阅 BadouAdmin 的核心文档以获取可用的钩子/事件列表及其参数。

## 8. 系统文件备份保护

开发时，如果需要替换系统中的文件，那么需要将文件路径写入`protectedFiles.php`文件中。
当插件`开启`时会替换系统原来的文件
当插件`关闭`后则恢复原来系统的文件

```php
// 文件需要自行创建 名称`protectedFiles.php`
// 文件中返回数组即可
// 需要保护的文件，插件卸载后恢复原来文件
return [
    'app/AppService.php'
];
```

## 9. 最佳实践

-   **命名规范**: 遵循 ThinkPHP 的命名规范，确保类名、文件名、方法名等清晰一致。
-   **模块化**: 保持插件功能的单一性，避免一个插件承担过多不相关的功能。
-   **错误处理**: 插件代码应包含适当的错误处理和日志记录，方便调试和维护。
-   **安全性**: 注意输入验证和输出过滤，防止 SQL 注入、XSS 等安全漏洞。
-   **兼容性**: 考虑插件在不同 BadouAdmin 版本间的兼容性。
-   **文档**: 为您的插件编写清晰的文档，说明其功能、配置和使用方法。

通过遵循这些指南，您可以有效地开发和维护 BadouAdmin 插件。
